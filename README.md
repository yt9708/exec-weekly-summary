# 高管周总结系统 · Exec Weekly Summary

> 让中高层管理者 **10 分钟内** 完成每周信息消化与决策确认

**用户端**：https://exec-weekly-summary.bonto.run/  
**管理后台**：https://exec-weekly-summary.bonto.run/manage  
**GitHub**：https://github.com/yt9708/exec-weekly-summary

---

## 需求背景

中高层管理者的核心困境不是**信息不够**，而是**信息太分散**——项目进度、OKR 进展、人事动态、待审批事项分布在多个系统（企业微信、合思、飞书、ERP、邮件等），每周需要自己拼凑全貌，耗费大量认知成本。

传统的周报方式（邮件收集、Excel 汇总、逐一登录各系统查看）存在以下痛点：

- **信息碎片化**：管理者需要在 5-6 个系统间来回切换
- **被动查询**：没有主动推送，容易遗漏关键决策节点
- **缺乏信号**：数据堆砌但没有「健康度」判断，绿/黄/红状态需要自己脑补
- **汇报成本高**：看完信息后还要重新整理向上汇报，重复劳动

---

## 产品价值

本产品将跨系统信息聚合后，按管理者的**阅读心流**结构化呈现，并主动推送到企业微信，核心差异在于：

| 维度 | 传统方式 | 本产品 |
|------|----------|--------|
| 信息获取 | 逐一登录各系统 | 跨系统聚合，一站式查看 |
| 呈现方式 | 邮件/Excel/Word | 可视化卡片，信号驱动 |
| 主动程度 | 管理者主动查询 | AI 摘要 + 定时推送 |
| 健康判断 | 自行脑补 | 绿/黄/红状态一目了然 |
| 向上汇报 | 需要重新整理 | AI 一键生成汇报摘要 |

## 设计思路

### 信息架构：管理者的阅读心流

```
总览（AI 摘要） → 决策（待处理事项） → 现状（业务体检）
→ 动态（团队/人事） → 预警（风险前瞻）
```

遵循管理者阅读周报的自然认知顺序：**先看全貌 → 再做决策 → 确认现状 → 了解人事 → 预警未来**。

### 核心设计原则

1. **信号优于数据**：不堆砌数字，而是给出绿/黄/红的健康判断
2. **主动优于被动**：周一早 8:30 自动推送到企业微信，无需登录
3. **决策优先**：待审批/待确认事项放在最显眼位置，支持一键跳转处理
4. **可消费**：AI 生成摘要可直接作为向上汇报的草稿

## 主要功能

### 1. AI 周报总览
基于全局数据自动生成整体状态摘要，包含：
- 本周核心结论（几句话概括全局）
- 需关注事项（可跳转详情）
- 下周风险预判
- 支持重新生成 & 一键复制为向上汇报草稿

### 2. 决策清单
聚合跨系统待处理事项，按优先级三级分类：
- 🆘 **紧急**：需要立即决策
- ⚡ **需处理**：本周内需完成
- ℹ️ **知会即可**：仅供参考

每项附来源系统标识（企微 / 合思 / 邮件）和跳转链接。

### 3. 本周动态速览
- **业务体检**：各部门核心指标进度条 + 异常标记
- **团队动态**：1on1 覆盖提醒、人事变动、生日/周年纪念一体化展示

### 4. 下周预警雷达
- 高风险节点与关键时间线
- 支持一键同步至日历

### 5. 管理后台（`/manage`）
对以下模块提供完整的增删改配置：
- 决策清单
- 事件跟踪
- 预警设置
- 业务体检指标
- 团队动态
- 推送渠道管理

### 6. 历史周报（`/history`）
支持历史周报回溯查看，方便追溯。

### 7. 多端推送
- 企业微信推送（图片卡片）
- 推送前自动截图
- 确认推送后锁定周报，不可修改

## 部署说明

### 环境变量

```
PORT=3456                    # 服务端口（可选，默认 3456）
DEEPSEEK_API_KEY=            # DeepSeek API Key（可选，不配置则使用规则降级）
DEEPSEEK_MODEL=deepseek-chat # AI 模型（可选）
BASE_URL=                    # 公网地址（推送截图用）
```

### 本地运行

```bash
git clone https://github.com/yt9708/exec-weekly-summary.git
cd exec-weekly-summary
npm install
npm start
```

访问 http://127.0.0.1:3456

### Docker

```bash
docker build -t exec-weekly-summary .
docker run -p 3457:3456 exec-weekly-summary
```

## 实测反馈与迭代思考

### 当前阶段：Demo 验证 ✅

本次以 Demo 展示为目标，数据为 Mock 模拟数据，核心验证信息架构与交互逻辑的合理性。

### 团队内部实测反馈

- 🔥 **决策清单** 和 **下周预警** 被认为对管理者最直接有价值
- 👍 **AI 摘要一键复制** 为向上汇报的功能实用性强
- 💡 管理后台的可配置性（增删改）得到了正面评价

### 下一步规划

#### P0 — 打通真实数据源（最重要）
- [ ] **企业微信**：对接企微开放平台 API，拉取真实审批、消息数据
- [ ] **合思**：对接合思开放平台，获取财务审批、预算数据
- [ ] **飞书**：对接飞书 API，获取 OKR 进度、审批、日历
- [ ] **内部 ERP**：对接企业内部系统 API

#### P1 — 推送能力完善
- [ ] **企业微信**：配置真实 CorpID/AgentID/Secret，实现真实推送
- [ ] **推送频率**：支持自定义（实时关键节点提醒 + 定时周报）
- [ ] **推送渠道**：支持飞书、邮件等多渠道

#### P2 — 个性化与智能化
- [ ] **模块订阅**：管理者可自定义订阅模块组合，降低信息噪音
- [ ] **绿/黄/红标准**：与各团队对齐判断标准
- [ ] **AI 规则优化**：基于历史反馈优化 AI 摘要生成

#### P3 — 运维与扩展
- [ ] **部署迁移**：从 Bonto 迁移至更稳定的生产环境
- [ ] **数据库**：引入 SQLite/PostgreSQL 替代 JSON 文件存储
- [ ] **权限管理**：支持多角色权限控制
- [ ] **数据可视化**：更多图表化呈现
