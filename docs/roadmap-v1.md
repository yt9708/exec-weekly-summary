# 高管周总结系统 · 开发路线图

> 基于 PRD v1 和 Demo 设计定稿（Stripe 风格）  
> 技术栈：Node.js + Express + EJS + Puppeteer + DeepSeek API  
> 里程碑目标：3 周内上线 MVP

---

## 总览

```
W1: 基础设施→数据→Web页面
W2: AI 生成→图片流水线→企微推送
W3: 联调→打磨→部署上线
```

---

## 阶段一：基础设施搭建（Day 1-2）

### Step 1.1 初始化项目
- **做什么**：在 `src/` 下创建 Node.js 项目骨架
- **产出**：`src/package.json`、Express 入口文件、基础路由结构
- **关键动作**：
  - `npm init` 初始化项目
  - 安装必要依赖（express, ejs, puppeteer, dotenv 等）
  - 创建目录结构：`routes/`、`views/`、`data/`、`services/`

### Step 1.2 模拟数据层
- **做什么**：创建四大模块的模拟 JSON 数据结构
- **产出**：`src/data/mock-weekly-report.json`（包含所有模块数据）
- **关键动作**：
  - 定义完整的数据 schema：决策事项、健康度、团队动态、预警
  - 填充与 Demo 一致的 mock 数据
  - 添加 API 接口 `GET /api/weekly-report` 返回数据

## 阶段二：Web 详情页（Day 3-5）

### Step 2.1 模板引擎与布局
- **做什么**：搭建 EJS 模板体系，复用 Demo 的 Stripe 样式
- **产出**：`src/views/layout.ejs` 和四个模块的局部模板
- **关键动作**：
  - 将 Demo 的 HTML/CSS 拆为 EJS 模板
  - 提取导航栏、头部、footer 为公共布局
  - 实现 route → controller → view 的数据渲染流程

### Step 2.2 本周总览 + 决策清单
- **做什么**：模块一、二的页面渲染和交互
- **产出**：可访问的 Web 页面，展示 AI 摘要和决策清单
- **关键动作**：
  - **模块一**：渲染三条摘要（带 🟢/🟡/🔴 标识），支持文字选中复制
  - **模块二**：
    - 每条事项显示四项要素：**事项标题 + 一句话背景描述 + 建议行动 + 来源标签**
    - 默认只展示 🆘（需要动作）和 ⚡（需要决策）两类
    - ℹ️（知会即可）默认折叠，用户可点击展开
    - **按紧急程度自动排序**，最紧急排最前
    - **标题可点击**跳转对应系统（MVP 阶段使用占位链接 #）

### Step 2.3 本周动态速览 + 下周预警
- **做什么**：模块三、四的页面渲染
- **产出**：完整四模块的 Web 页面
- **关键动作**：
  - **模块三 · 业务体检区**：
    - 项目里程碑健康度 🟢/🟡/🔴（2×2 网格布局）
    - **异常自动置顶**（红灯优先，绿灯不占视觉焦点）
    - 延期项目及原因标注
    - 跨团队依赖阻塞及责任人
    - 项目进度趋势（变好/恶化指示）
  - **模块三 · 团队动态区**：
    - 1on1 覆盖提醒（超过 2 周未面谈的下属名单）
    - 人事动态（入职 / 离职 / 转岗）
    - 招聘进展漏斗状态
    - 重要日期提醒（生日、工作周年纪念）
  - **模块四 · 下周预警**：
    - 高风险交付节点（标注风险等级）
    - 重要会议 / 述职 / 汇报（附议程或准备材料链接位置）
    - 跨团队资源冲突预警
    - **每条预警标注"建议最迟准备时间"**

## 阶段三：AI 摘要生成（Day 6-8）

### Step 3.1 DeepSeek API 接入
- **做什么**：对接 DeepSeek 模型，实现"本周总览"的 AI 生成逻辑
- **产出**：`src/services/ai-service.js`
- **关键动作**：
  - 编写 prompt 模板（输入模块二至四的结构化数据 → 输出 3-5 句摘要）
  - **数据缺失处理**：prompt 中明确要求 AI 跳过数据不足的维度，不产生"无数据"等无效文案
  - **重试与降级**：API 调用失败时自动重试 2 次；仍失败则返回上次缓存摘要并记录日志
  - 实现 `generateSummary(data) → summaryText` 函数
  - 添加环境变量配置（API Key 等）

### Step 3.2 手动刷新 + 快照锁定
- **做什么**：Web 页面点击"重新生成"调用 AI 接口；同时实现推送快照隔离
- **产出**：`POST /api/report/regenerate` 接口 + 推送快照存储机制
- **关键动作**：
  - 后端添加刷新路由，调用 AI 服务
  - **推送快照存储**：推送时生成的 AI 摘要持久化保存为"推送版本"（`data/snapshots/`）
  - **版本隔离**：手动刷新仅更新 Web 页面显示的"实时版本"，不覆盖推送版本
  - 前端按钮绑定 AJAX 请求，局部刷新总览卡片

## 阶段四：图片生成与推送（Day 9-12）

### Step 4.1 Puppeteer 截图流水线
- **做什么**：将 Web 页面渲染为推送图片
- **产出**：`src/services/screenshot-service.js`
- **关键动作**：
  - 启动 headless 浏览器打开 Web 页面
  - 设置 750×1334 视口（手机比例）
  - 截图保存为 `generate/report-screenshot.png`
  - 支持在图片中截取"摘要+决策数量+健康度概览"区域

### Step 4.2 企微推送接入
- **做什么**：通过企微自建应用 API 发送图片卡片
- **产出**：`src/services/wecom-service.js`
- **关键动作**：
  - 获取企业微信 access_token
  - 上传图片素材到企微临时素材库
  - 构造图文消息卡片，包含图片和跳转链接
  - 实现定时推送（每周一 8:30）

### Step 4.3 定时任务
- **做什么**：自动化每周一推送流程
- **产出**：`src/services/scheduler.js`
- **关键动作**：
  - 使用 node-cron 设置每周一 8:30 定时任务
  - 任务流程：加载数据 → 生成 AI 摘要 → 渲染页面 → 截图 → 推送企微

## 阶段五：联调与上线（Day 13-15）

### Step 5.1 整链联调
- **做什么**：跑通完整流程，修复问题
- **产出**：可完整运行的 MVP 版本
- **关键动作**：
  - 数据 → AI → 页面 → 截图 → 推送 全链路验证
  - **风险验证重点**：
    - Puppeteer Windows 环境兼容性（沙箱模式、路径编码）
    - DeepSeek API 调用失败的重试与降级行为
    - 企微 access_token 过期自动刷新机制
    - 定时任务异常时的日志记录与告警
  - 推送快照与实时版本隔离验证
  - 边缘情况处理

### Step 5.2 界面打磨
- **做什么**：对照 Demo 设计稿微调视觉效果
- **产出**：像素级匹配的正式页面
- **关键动作**：
  - 核对颜色、间距、字体
  - 手机端适配

### Step 5.3 部署上线
- **做什么**：部署到服务器
- **产出**：生产可用的服务
- **关键动作**：
  - 部署文档
  - 环境变量配置
  - 服务进程管理（PM2 或类似工具）
