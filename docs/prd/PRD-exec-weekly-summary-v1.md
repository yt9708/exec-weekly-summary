# PRD：高管周总结系统 v1

> 版本：v1（MVP）  
> 状态：草案  
> 创建日期：2026-05-16

---

## 1. 背景与痛点

中高层管理者（总监 / VP）每周面临的核心困境不是"信息不够"，而是"信息太分散"：

- 项目进度在 PM 系统，团队目标分散在不同文档和汇报中，人员动态在 HR 系统，预算状态在财务工具（合思¹）——管理者需要自己跨系统拼凑全貌，耗费大量认知成本。
- 尽管公司有周报制度，但每位管理者仍依赖个人习惯和经验手动整理，缺乏统一、自动化的周汇总机制。
- 管理者的时间高度碎片化，难以抽出完整时间逐一登录各系统查阅最新状态。
- 高层级管理者（VP）看到的往往是层层汇总后的二手信息，缺少对一线信号的直接感知。
- 向上汇报时，每次都需要重新组织和梳理信息，缺乏可直接复用的周报产出素材。

---

## 2. 目标与成功指标

**核心目标：** 让中高层管理者每周用 ≤10 分钟掌握全局，并清楚自己本周需要做什么决策。

**成功指标：**

| 指标 | 说明 |
|---|---|
| 阅读效率 | 管理者每周一接收周报后，≤10 分钟可完成阅读并掌握全局状态 |
| 决策覆盖 | "决策清单"准确识别所有待处理事项，减少关键事项遗漏 |
| 输出复用 | AI 生成的"本周总览"可直接复制作为向上汇报的周报草稿 |
| 系统替代 | 周报覆盖关键维度，替代管理者逐一登录各系统查数据的习惯 |

---

## 3. 用户角色与范围

### 目标用户（MVP）

| 角色 | 关注维度 | 说明 |
|---|---|---|
| 董事长 / CEO | 公司级整体健康度、战略风险信号、全局趋势 | 看跨业务线汇总信号，关注异常 |
| 各部门部长 | 本部门/跨部门周报、决策清单、业务健康度 | 核心用户，日常使用频率最高 |

### 范围边界

- **MVP 用户数**：约 10 人（董事长 + CEO + 各部部长）
- **暂不覆盖**：经理级、主管级、普通员工（后续版本纳入）
- **系统管理员**：MVP 阶段由开发人员手动维护配置，后续版本提供管理后台

## 4. 核心功能模块

### 4.1 模块一：本周总览（AI 生成）

**定位：** 管理者打开周报第一眼看到的内容，30 秒内可速览全局。作为模块二至模块四的概述提要。

**内容规范：**

- AI 基于模块二至四的数据自动生成 **3-5 句话**
- 每句话包含三要素：
  1. 本周整体健康状态判断（🟢 / 🟡 / 🔴）
  2. 最需要关注的 1-2 件事
  3. 下周最大的风险提示
- 语气：简洁、直接、结论先行

**输出特性：**

- 文字可直接复制粘贴，作为向上汇报的周报草稿
- AI 模型：DeepSeek
- 数据缺失处理：如果某模块数据不足，AI 自动跳过该维度，不产生"无数据"等无效文案
- 管理者可在 Web 页面手动触发"刷新重新生成"

**推送快照规则：** 每周一 8:30 推送时，AI 生成的摘要以推送时刻的快照为准，自动锁定。
  管理者后续在 Web 页面上手动刷新不会触发企微重新推送，避免已推送内容与页面内容不一致。

**交互路径：** 嵌入 Web 详情页顶部，企微推送图片中也包含摘要区域

---

### 4.2 模块二：我的决策清单

**定位：** 直接回答"我这周需要做什么"，是整个周报最核心的行动模块。

**任务分级：**

| 级别 | 标识 | 说明 |
|---|---|---|
| 需要动作 | 🆘 | 待审批/待决策/待介入，必须处理 |
| 需要决策 | ⚡ | 需要管理者拍板决定的事项 |
| 知会即可 | ℹ️ | 了解即可，默认折叠 |

**事项来源与跳转：**

- **卡住等待拍板的项目决策** → 附文档/邮件链接，一键跳转
- **待审批的资源 / 预算申请** → 跳转合思审批系统
- **需要介入的跨团队协调问题** → 附企微群链接
- **下属发起的 Escalation 未处理项** → 附来源信息

**展示规则：**

- 每条显示：**事项标题 + 一句话背景描述 + 建议行动 + 来源标签**
- 标题可点击，直接跳转对应系统进行处理
- 按紧急程度自动排序，最紧急的排最前
- 默认只展示"需要动作"和"需要决策"两类，"知会即可"折叠收起，用户可展开查看

**数据聚合来源：**

- **目标数据源**（后续阶段对接）：企微 @ 未回复消息、合思待审批单、企业邮箱中标记重要未读邮件
- **MVP 阶段**：以上全部使用模拟数据，通过静态 JSON 文件注入，数据结构已预留对接字段

### 4.3 模块三：本周动态速览

**定位：** 整合"业务与目标健康度"和"团队动态"两个维度，让管理者一次性看完本周业务和人两方面的重要变化。分为两个子区域。

> **跨模块说明：** 同一事项可能同时出现在模块二（作为待决策事项）和本模块业务体检区（作为业务状态）。两者定位不同——模块二推行动，本模块给背景——同时展示属于设计预期，非重复。

#### 4.3.1 业务体检区

- **项目里程碑**：各团队重要节点完成情况（🟢 / 🟡 / 🔴），异常自动置顶
- **项目进度趋势**：落后指标是在变好还是在恶化
- **延期项目**：本周延期的项目及原因标注
- **跨团队依赖阻塞**：卡在其他团队的依赖项及责任人
- **呈现原则**：不堆砌"完成了多少"，突出"按这个速度能不能达成"；绿灯项目不占版面

#### 4.3.2 团队动态区

- **1on1 覆盖**：哪些下属超过 2 周未进行一对一面谈
- **人事动态**：本周入职 / 离职 / 转岗情况
- **招聘进展**：在招岗位的漏斗状态
- **重要日期**：团队成员生日、工作周年纪念日提醒

### 4.4 模块四：下周预警

**定位：** 让管理者提前有准备，而不是制造焦虑。只列真正需要提前行动的事项。

**内容清单：**

- **高风险交付节点**：下周到期的关键项目节点，标注风险等级
- **重要会议 / 述职 / 汇报**：提前提示，附议程或准备材料链接
- **跨团队资源冲突预警**：下周可能出现的资源争抢情况
- **建议准备时间**：每条预警标注"建议最迟准备时间"，方便管理者提前安排日程

## 5. 非功能需求

### 5.1 输出形式

**双通道输出：**

- **企微推送（触达层）**：
  - 每周一 8:30 通过企微自建应用/机器人推送图片卡片
  - 图片内容包含：本周总览摘要 + 决策清单数量 + 健康度概览
  - 卡片底部附"查看完整周报"按钮，点击跳转 Web 详情页
- **Web 详情页（交互层）**：
  - 展示完整的四个模块内容，支持交互操作（展开/折叠、刷新生成、历史周报归档查看）
  - 适配手机端浏览器，方便移动端查看
  - **图片设计规范**：MVP 阶段暂固定 750×1334（手机屏比例），具体设计稿在开发阶段确定

### 5.2 数据集成策略

**MVP 阶段：**

- 使用模拟数据（Mock Data）构建前端展示和推送流程
- 模拟数据覆盖：决策事项、项目里程碑、团队动态、预警信息
- 数据结构预留对接字段，便于后续替换为真实 API

**后续阶段：**

- 企业微信 API：读取消息、群聊、通讯录
- 合思 API：读取审批单、费用数据
- 企业邮箱：读取重要邮件

### 5.3 AI 能力

- **模型**：DeepSeek（CodeBuddy 提供统一模型接入层，可通过 Node.js HTTP 请求直接调用 DeepSeek API）
- **用途**：生成模块一"本周总览"的 3-5 句话摘要
- **输入**：模块二至四的结构化数据摘要
- **输出**：结构化健康判断 + 关注事项 + 风险提示
- **调用时机**：每周一推送前自动触发，此次结果锁定为当周推送快照；管理者可在 Web 页面手动触发重新生成（仅更新 Web 页面，不触发重新推送）

## 6. MVP 范围与里程碑

### MVP 范围

| 维度 | 包含 | 不包含 |
|---|---|---|
| 用户 | 董事长 / CEO、各部部长（约 10 人） | 经理级及以下、系统管理后台 |
| 模块 | 四个完整模块 | 历史周报趋势对比分析 |
| 数据 | 模拟数据 | 真实 API 对接 |
| 推送 | 企微机器人推送图片 + 卡片链接 | 飞书、邮件等其他渠道 |
| AI | 本周总览生成（DeepSeek） | 其他 AI 功能 |

### 技术栈

| 层 | 方案 |
|---|---|
| 后端框架 | Node.js + Express |
| 页面渲染 | EJS 模板引擎 |
| 图片生成 | Puppeteer（截图 Web 页面生成推送图片） |
| AI 接入 | DeepSeek API（通过 Node.js HTTP 请求调用） |
| 数据存储 | 本地 JSON 文件（MVP 阶段，无需数据库） |
| 部署 | 单进程 Node 服务 |

### 里程碑计划（2-3 周）

| 阶段 | 周期 | 产出 |
|---|---|---|
| **W1：基础设施 + Web 页面** | 第 1 周 | Node.js 项目搭建 → 模拟数据结构定义 → 四个模块的 Web 页面（EJS 模板）→ 基础路由和导航 |
| **W2：图片生成 + 推送** | 第 2 周 | Puppeteer 截图流水线 → AI 摘要生成对接 → 企微机器人消息推送接入 → 完整推送流程跑通 |
| **W3：联调与上线** | 第 3 周 | 整体联调测试 → 界面打磨 → 企微配置联调 → 上线部署 |

### 后续规划（MVP 后）

- 真实数据源对接（企微 API、合思 API、企业邮箱）
- 推送渠道扩展（飞书、邮件）
- 系统管理员后台（用户管理、数据源配置）
- 历史周报归档（可回顾查看历史各期周报快照）
- 趋势对比分析（跨周数据对比、指标变化趋势）
